Agent Runner

Provider abstraction layer, tool orchestration, and LLM routing engine

Overview

The Agent Runner is the core execution layer of Hermes Agent. It handles provider abstraction, manages the conversation loop, orchestrates tool execution, and routes requests to the appropriate LLM backends. This layer is designed to be provider-agnostic, allowing seamless switching between different LLM services.

The runner follows a message-in, function-calls-out model where user messages trigger a continuous loop of reasoning, tool invocation, and response generation until the task is complete.

Provider Architecture

All LLM providers implement a common BaseAdapter interface, ensuring consistent behavior across different backends. Each adapter handles provider-specific API formatting, response parsing, and error handling.

Base Adapter Interface

class BaseAdapter(ABC):
    async def chat(messages, tools, model):
        """Send chat request to provider"""
        pass

    async def vision(image_url, prompt):
        """Handle image understanding"""
        pass

    async def count_tokens(text, model):
        """Count tokens for context management"""
        pass

    def parse_response(response):
        """Parse provider-specific response"""
        pass

LLM Routing Logic

The ProviderManager selects the appropriate adapter based on:

  • Model name prefix — Routes to provider based on provider:model format
  • Cost optimization — Falls back to cheaper models for simple tasks
  • Capability matching — Vision tasks route to vision-capable models
  • Config priority — User-defined preferences in config.yaml
def route_request(model_name, task_type):
    if model_name.startswith("gpt"):
        return OpenAIAdapter()
    elif model_name.startswith("claude"):
        return AnthropicAdapter()
    elif model_name.startswith("gemini"):
        return GeminiAdapter()
    # ... other providers
