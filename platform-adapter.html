Platform Adapters

Unified messaging gateway supporting Telegram, Discord, Feishu, QQ, Webhook, and more. All platforms are abstracted through a common interface for seamless message routing and handling.

Architecture Overview

The platform adapter layer sits between external messaging platforms and the core Hermes Agent engine. It normalizes all incoming messages into a unified format and routes outgoing messages back to the appropriate platform.

Unified Message Interface

All platform adapters normalize messages into a standard UnifiedMessage format before processing:

class UnifiedMessage: # Identity platform: str # "telegram", "discord", "feishu", "qq", "webhook" message_id: str # Platform-specific unique ID # Sender user_id: str # Platform user identifier username: str # Display name or handle chat_id: str # Channel/group identifier # Content content: str # Text content (normalized) raw_content: Any # Platform-specific original payload # Metadata message_type: str # "text", "image", "audio", "video", "file" timestamp: float # Unix timestamp metadata: Dict[str, Any] # Platform-specific extras

Incoming Message Handling

When a message arrives from any platform, the adapter performs the following steps:

  • 1. Receive — Platform-specific webhook or polling captures the raw event
  • 2. Parse — Extract platform-specific fields from the payload
  • 3. Normalize — Convert to UnifiedMessage format
  • 4. Validate — Check message integrity and required fields
  • 5. Dispatch — Forward to the core message router
# Example: Telegram incoming message flow async def handle_update(update: Update): message = update.message # Parse platform-specific fields unified = UnifiedMessage( platform="telegram", message_id=str(message.message_id), user_id=str(message.from_user.id), username=message.from_user.username, chat_id=str(message.chat.id), content=message.text or "", raw_content=message, message_type="text", timestamp=message.date.timestamp() ) # Dispatch to core engine await message_router.route(unified)

Outgoing Message Handling

Responses are routed back through the adapter layer to the correct platform:

  • 1. Format — Core engine returns platform-agnostic response data
  • 2. Adapt — Adapter converts to platform-specific message format
  • 3. Send — Deliver via platform API (REST, WebSocket, etc.)
  • 4. Confirm — Update message status and handle errors
# Example: Platform adapter reply interface class PlatformAdapter(ABC): @abstractmethod async def send_message( self, chat_id: str, content: str, **kwargs ) -> MessageResult: """Send a message to the specified chat""" pass @abstractmethod async def send_image( self, chat_id: str, image_url: str, **kwargs ) -> MessageResult: """Send an image to the specified chat""" pass

Unified Message Routing

The MessageRouter is the central dispatcher that routes messages between platforms and the core agent:

class MessageRouter: def __init__(self, adapters: Dict[str, PlatformAdapter]): self.adapters = adapters self.middlewares = [] async def route(self, message: UnifiedMessage) -> Response: # Apply middleware chain for mw in self.middlewares: message = await mw.process(message) # Process with core agent response = await self.agent.process(message) # Route response back to platform adapter = self.adapters.get(message.platform) await adapter.send_message(message.chat_id, response.content) return response

Adding a New Platform

To add support for a new messaging platform, implement the PlatformAdapter interface:

from abc import ABC, abstractmethod class PlatformAdapter(ABC): """Base class for all platform adapters""" @property abstract def platform_name(self) -> str: """Unique identifier for this platform""" pass @abstractmethod async def initialize(self, config: Dict) -> None: """Initialize the adapter with configuration""" pass @abstractmethod async def start(self) -> None: """Start listening for messages (webhook/polling)""" pass @abstractmethod async def stop(self) -> None: """Gracefully stop the adapter""" pass

Place your new adapter in gateway/platforms/your_platform.py and register it in the adapter registry.
